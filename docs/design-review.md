# 且慢主理人看板视觉改造审查文档

状态：第一轮改造已实施，待产品与可访问性复核  
审查日期：2026-07-28  
适用项目：`qieman-manager-dashboard` macOS App  
关联规范：`docs/design-system.md`  
主要实现：`macos-app/Design/AppPalette.swift`、`macos-app/Views/SharedComponents.swift`

## 一、审查结论

当前界面已经形成稳定的蓝灰色投资工具风格，信息架构、状态反馈、深浅色适配和 macOS 原生能力都较完整，不需要推倒重做。

本轮建议采用保留式改造，重点解决以下问题：

1. 8-10pt 文字使用范围过大，AI 报告、平台详情和持仓辅助信息阅读压力明显。
2. 页面、分组、卡片、子卡片、Badge 同时使用底板、圆角、描边和阴影，容器层级偏重。
3. 品牌蓝、状态色和多种辅助强调色同时出现，部分统计区域颜色数量超过信息语义所需。
4. AI 研判页面缺少渐进披露，日志、结论、证据、标的建议同时展开。
5. 自定义顶部栏与系统工具栏职责重叠，侧边栏选中态同时使用色带、填充、描边、发光和位移。

本轮目标不是降低信息量，而是减少视觉包装，让用户更快区分：

- 当前最重要的结论
- 可以立即执行的操作
- 可按需展开的证据
- 仅用于追溯的元数据

## 二、设计定位

### 2.1 产品定位

原生 macOS 投资数据看板，服务于需要持续查看持仓、平台调仓、关注标的和 AI 分析结果的个人投资者。

界面应保持：

- 沉稳
- 清晰
- 高信息效率
- 原生 macOS 工具感
- 对金融风险和数据时效有明确表达

不采用营销页面式的大标题、大留白、滚动叙事或装饰性高动效。

### 2.2 改造模式

采用 `Redesign Preserve`：

- 保留现有信息架构
- 保留蓝灰色品牌基调
- 保留红涨绿跌的中国市场惯例
- 保留现有业务文案和功能入口
- 保留键盘快捷键、菜单栏、右键菜单和窗口行为
- 优先修改字体、间距、表面层级和内容披露方式

### 2.3 设计参数

| 参数 | 当前判断 | 目标 | 说明 |
|---|---:|---:|---|
| `DESIGN_VARIANCE` | 4 | 4 | 保持稳定、可预测的工具布局 |
| `MOTION_INTENSITY` | 3 | 3 | 仅保留反馈型动效 |
| `VISUAL_DENSITY` | 8 | 7 | 保留高密度，但提高阅读性 |

## 四、现状中应保留的设计

### 4.1 设计 token

`AppPalette` 已提供圆角、间距、字体、语义色、阴影、动效和材料入口，应继续作为唯一视觉配置源。

应保留：

- 统一的间距阶梯
- 统一的圆角阶梯
- `marketGain` 与 `marketLoss`
- Light 和 Dark 独立调色
- `accessibilityReduceMotion`
- `accessibilityReduceTransparency`
- `legibilityWeight`
- `colorSchemeContrast`

### 4.2 macOS 原生能力

以下实现符合桌面端使用习惯，应避免在视觉改造中回退：

- `NavigationSplitView`
- 可折叠侧边栏
- 可调整和记忆窗口尺寸
- 标准交通灯
- App、Edit、View、Window、Help 菜单
- `Command-1` 到 `Command-6` 页面导航
- `Command-R` 刷新
- `Command-F` 页面搜索
- `Command-K` 快捷操作
- `Command-,` 设置
- Dock 右键菜单
- 关键列表项右键菜单
- 表单的 Return 默认操作与 Escape 取消

### 4.3 业务语义

以下颜色和状态语义必须保持稳定：

- 红色表示上涨
- 绿色表示下跌
- 危险操作使用 `danger`
- 警告使用 `warning`
- 失败状态不能只依赖颜色表达
- 数据缺失与数值为零必须保持不同语义

## 五、问题与优先级

| 优先级 | 问题 | 用户影响 | 涉及区域 |
|---|---|---|---|
| P0 | 正文和辅助文字偏小 | 长时间阅读疲劳，关键信息易漏读 | 全局、AI、平台、持仓 |
| P0 | 容器层级过多 | 信息优先级被底板和描边稀释 | 全局 |
| P0 | AI 页面缺少渐进披露 | 结论、日志、证据相互争抢注意力 | AI 研判 |
| P1 | 顶部栏与原生工具栏职责重叠 | 占用垂直空间，原生感下降 | App Shell |
| P1 | 侧边栏选中效果叠加过多 | 导航视觉过强，干扰内容区 | App Shell |
| P1 | 策略雷达使用重复卡片和评分条 | 信息比较效率低，名称与表现形式不一致 | 平台动态 |
| P1 | 状态色被用于装饰性区分 | 同屏颜色过多，金融语义变弱 | 总览、平台 |
| P2 | 设置同时存在主导航入口和独立窗口 | 信息架构略显重复 | 设置 |
| P2 | 固定字号而非系统语义字号 | 对系统字体和辅助功能响应不足 | 全局 |

## 六、修改方案

### 6.1 字体系统

#### 当前问题

当前字号从 8pt 开始，且大量说明文字使用 9-10pt。真实运行界面中，AI 报告、策略细节、日志和表格辅助信息已经低于舒适阅读尺寸。

#### 建议字号

保留现有枚举名称以降低迁移成本，调整实际字号和使用边界：

| Token | 当前 | 建议 | 使用范围 |
|---|---:|---:|---|
| `.caption2` | 8 | 9 | 图表轴、极少量法律或系统元数据 |
| `.caption` | 9 | 10 | 时间戳、代码、来源 |
| `.footnote` | 10 | 11 | 说明、证据摘要、次级详情 |
| `.subheadline` | 11 | 12 | 卡片摘要、辅助正文 |
| `.body` | 12 | 13 | 常规正文、列表标题、表格内容 |
| `.headline` | 13 | 14 | Section 标题、主要按钮、侧边栏 |
| `.title3` | 14 | 15 | 面板标题 |
| `.title2` | 16 | 17 | 页面内重点标题 |
| `.title` | 18 | 20 | 页面标题 |
| `.largeTitle` | 22 | 24 | Onboarding 和空状态主标题 |

#### 使用规则

- 11pt 以下文字不能承载操作建议、风险说明或正文。
- 9-10pt 只用于时间、来源、代码和图表坐标。
- 金额和百分比继续使用等宽数字，但不默认缩小字号。
- AI 生成内容正文使用 12-13pt，行距至少 1.35 倍。
- 长文本阅读宽度控制在 720-820pt。
- 表格在窗口宽度不足时优先减少次级列，而不是继续缩小字体。
- 后续可逐步将正文映射到 SwiftUI 语义字体，避免继续扩散固定字号。

### 6.2 表面与容器层级

#### 目标层级

每个页面最多使用三层可见表面：

| 层级 | 用途 | 背景 | 描边 | 阴影 |
|---|---|---|---|---|
| S0 | 页面画布 | `surface` 或 material | 无 | 无 |
| S1 | 内容分组 | 透明或极弱 `card` | 可选单条分隔线 | 无 |
| S2 | 可交互内容 | `card` 或 `cardStrong` | 细描边 | 默认无 |
| S3 | 选中、浮层、强提醒 | 语义色浅底或 material | 强描边 | 可选 |

S3 仅用于选中状态、Popover、Sheet、Toast 和需要立即处理的警告，不作为普通内容的默认容器。

#### 修改规则

- `SectionCard` 默认移除阴影。
- 普通 Section 不再同时使用背景、裁切、描边和阴影。
- `StatChip` 优先改为无底板指标，使用对齐和间距建立分组。
- 卡片内部不再嵌套相同圆角、相同颜色和相同描边的子卡片。
- 深色模式普通内容不使用黑色投影制造层级。
- 分组优先使用留白和单条分隔线。
- 只有可点击、可选择、可展开的行才使用完整 hover 表面。

#### 公共组件建议

新增或调整以下公共组件：

- `SectionGroup`：无阴影、弱背景或透明背景的内容分组。
- `MetricStrip`：横向数字指标，不为每个指标单独创建卡片。
- `ReadingPanel`：限制宽度、提高行距的长文本容器。
- `DisclosureEvidenceGroup`：默认收起的证据和日志区域。
- `InteractiveRow`：统一列表行 hover、pressed、selected 状态。

### 6.3 色彩系统

#### 保留

- 品牌蓝
- 蓝灰色中性背景
- 红涨绿跌
- `warning`、`danger`、`info`

#### 调整

- 品牌蓝仅用于主要操作、链接、选中轨道和 App 专属强调。
- Toggle、Picker、Radio 等标准系统控件优先遵循 macOS 系统 Accent Color。
- `accentWarm` 不再用于无风险语义的普通统计卡片。
- 普通统计数字使用 `ink`，只有异常、风险、涨跌和状态才使用彩色。
- 同一个统计区域最多保留一个品牌强调色和必要的语义状态色。
- 装饰性图标底板降低饱和度，避免每个 Section 都出现蓝色方形图标框。

### 6.4 动效与交互反馈

#### 保留

- 页面切换淡入
- Disclosure 展开收起
- 按钮 pressed 反馈
- 列表 hover
- 选中状态过渡

#### 调整

- 侧边栏和普通列表行取消 hover 上浮。
- 取消普通导航项的发光阴影。
- 小型按钮 pressed 缩放从 `0.965` 调整到 `0.98`，避免视觉跳动。
- 表格行仅改变背景或描边，不做缩放。
- 动效只表达反馈和状态变化，不用于装饰。
- 继续完整遵循 Reduce Motion。

### 6.5 App Shell 与顶部栏

#### 当前问题

系统窗口已经配置 unified toolbar，但主要页面仍使用自定义顶部栏展示页面标题、运行模式、侧边栏按钮和刷新按钮。

#### 建议

- 将侧边栏按钮移入原生 toolbar leading 位置。
- 将刷新按钮放入 toolbar primary action。
- 页面标题使用导航标题或 toolbar principal 区域。
- “原生直连”降级为紧凑状态信息，不占用页面标题下方独立一行。
- 删除内容区顶部的重复背景和 Divider。
- 保留双击标题栏缩放窗口的原生行为。
- toolbar 高度遵循系统默认，不增加额外垂直 padding。

### 6.6 主侧边栏

#### 建议

- 保留 3pt 品牌色选中轨道。
- 保留浅色选中背景。
- 移除选中发光。
- 移除 hover 上浮。
- 非选中图标不再使用持续可见的独立底板。
- Badge 只用于真实数量，不用于装饰或普通状态。
- 优先评估 `.listStyle(.sidebar)`，若继续使用自定义 ScrollView，应保持系统 material 和紧凑行高。

### 6.7 总览

#### 今日看点

- 保留四个摘要指标。
- 将普通指标文字统一为中性色。
- 仅待确认、异常回撤等状态使用语义色。
- 摘要项保持整行可点击，但取消卡片上浮和发光。

#### AI 趋势摘要

- 首屏只显示结论、风险等级、数据时点和一项主要操作。
- 摘要正文最多显示 3-4 行。
- 短期、中期、长期改为紧凑比较行，不使用三张等权卡片。
- 板块观点默认显示前 3 项，其余通过“查看完整报告”进入 AI 页面。
- 总览不展示完整证据链。

#### 最近调仓与最近发言

- Section 外框改为弱分组。
- 行本身保留交互背景。
- 元数据减少中点式串联，按时间、来源、互动量分列或换行。

### 6.8 我的持仓

#### 摘要区

- 总持仓、总收益、今日涨跌等指标改为 `MetricStrip`。
- 涨跌金额与涨跌率使用红绿语义色。
- 其他金额保持中性色。

#### 资产总表

- 保留现有高密度表格模式。
- 行标题和主要金额提高到 12-13pt。
- 次要代码、日期和来源使用 10-11pt。
- AI 观察摘要默认显示一行结论，详细依据通过 Disclosure 展开。
- 操作按钮在 hover 或选中时显示，减少常驻图标噪声。
- 窄窗口优先隐藏次要列并提供详情抽屉。

#### 组合诊断与收益归因

- 诊断项按风险等级排序。
- 普通状态使用中性色，只有“需要留意”和“高风险”使用警告色。
- 图表与数字共享同一个视觉重点，避免同时使用彩色图例、彩色数字和彩色卡片。

### 6.9 平台动态

#### 策略雷达

当前区域由五个统计卡片和五个评分卡片组成，且使用进度条表达多个并非连续进度的指标。

建议：

- 将“主理人策略雷达”更名为“策略概览”，除非后续实现真正的雷达或多维比较视图。
- 五个基础数量改为单行 `MetricStrip`。
- 评分项改为按重要性排序的信号列表。
- 每项显示名称、核心值、结论和简短解释。
- 取消带背景轨道的进度条。
- 颜色只表达积极、警告和数据不足，不按卡片类别分配不同颜色。

#### 调仓浏览

- 保留左侧动作列表、右侧详情的 master-detail 结构。
- 左侧选中态使用单一选中背景和轨道。
- 右侧关键数值形成统一对齐的指标行。
- 来源、日期和原文入口降为次级区域。
- 分页保留在列表底部，并增加键盘左右键支持。

### 6.10 AI 研判

AI 页面是本轮优先级最高的页面级改造。

#### 信息顺序

页面从上到下调整为：

1. 当前结论
2. 风险级别与有效期
3. 最高优先级的 1-3 项动作
4. 标的建议列表
5. 执行前复核
6. 证据与完整报告
7. 实时日志

#### 实时日志

- 默认收起。
- 分析运行中自动展开最近 3-5 条。
- 完成后显示状态、耗时和日志数量。
- 完整日志放入 Disclosure 或独立详情 Sheet。
- 错误日志在摘要区域提供清晰的失败原因和重试入口。

#### 标的建议

每个标的默认显示：

- 标的名称
- 建议
- 置信度
- 一句话理由
- 触发条件

以下内容默认收起：

- 完整依据
- 失效条件细节
- 数据来源
- 风险证据
- 原始模型输出

#### 阅读体验

- 主报告最大宽度 820pt。
- 正文至少 12pt。
- 长段落拆成短段或结构化条目。
- 风险提示不使用低对比度小字。
- “仅供研究”等免责声明保持可见，但不与主要结论争抢层级。

### 6.11 设置中心

- 保留四个设置分区。
- 独立 Settings 窗口优先使用原生设置导航形式。
- 主 App 中的设置入口可保留，用于统一应用内导航。
- 设置项优先使用 `Form`、`Section`、Toggle 和 Picker 的系统布局。
- 减少“设置导航卡片、内容大卡、设置子卡片”的三重嵌套。
- 危险操作与普通设置分组分离。
- “退出应用”等操作不与本地数据信息放在同一视觉层级。

## 八、实施顺序

### Phase 0：建立视觉基线

1. 保存当前总览、持仓、平台、AI、设置的 Light 和 Dark 截图。
2. 截图尺寸至少覆盖 860x600、1200x800、1440x900。
3. 记录 Reduce Transparency、Reduce Motion、Increase Contrast 下的基线。
4. 确认现有功能和快捷键清单。

### Phase 1：字体和公共表面

1. 调整字体 token。
2. 修改 `SectionCard`、`StatChip`、`InteractiveSurfaceModifier`。
3. 移除普通卡片阴影和 hover 上浮。
4. 新增 `MetricStrip`、`SectionGroup`、`ReadingPanel`。
5. 修复因字号增大产生的截断和布局溢出。

### Phase 2：App Shell 和总览

1. 将顶部操作迁入原生 toolbar。
2. 简化侧边栏。
3. 改造今日看点。
4. 压缩总览 AI 摘要。
5. 验证窗口最小尺寸。

### Phase 3：平台与 AI

1. 改造策略概览。
2. 优化调仓 master-detail。
3. 重排 AI 页面信息顺序。
4. 默认收起实时日志。

## 九、验收标准

### 9.1 视觉层级

- 任意普通内容区域不超过三层可见表面。
- 普通 Section 不同时使用强背景、完整描边和阴影。
- 深色模式普通卡片不使用黑色投影。
- 同一页面圆角体系保持一致。
- 同一统计区域不使用无语义的多色卡片。

### 9.2 字体与阅读

- 11pt 以下文字不承载正文、操作建议或风险说明。
- AI 正文达到 12pt 以上。
- 页面标题、Section 标题、行标题形成可辨认的三级层级。
- 1200x800 下主要正文无需缩放即可舒适阅读。
- 字号增加后不出现主要 CTA、表格标题和导航文字截断。

### 9.3 App Shell

- toolbar 使用系统高度。
- 侧边栏按钮、刷新按钮和标题不再由内容区重复模拟。
- 侧边栏选中态不使用发光和位移。
- 窗口交通灯、拖动、缩放、全屏和 Split View 正常。

### 9.4 页面级

- 总览首屏能明确看到资产、今日风险和 AI 结论。
- 平台策略区域不再由两排等权卡片和进度条构成。
- AI 页面首屏先出现结论和动作，而不是历史日志。
- AI 完整日志默认收起。
- 持仓表格在最小窗口宽度下仍可识别标的、金额和涨跌。
- 设置页不出现三层以上卡片嵌套。

### 9.5 交互与状态

- Hover 只用于表达可交互性。
- Pressed 状态不产生明显跳动。
- Loading 使用与最终布局匹配的骨架或内联状态。
- Empty 状态说明如何产生数据。
- Error 状态包含原因、恢复方式和复制入口。
- Escape、Return、Delete 和现有 Command 快捷键行为不回退。

### 9.6 可访问性

- Light 和 Dark 均通过视觉检查。
- Reduce Motion 下无装饰动画。
- Reduce Transparency 下材料替换为不透明背景。
- Increase Contrast 下边界、文字和选中态清晰。
- Bold Text 下布局不截断。
- icon-only 按钮具有可理解的 VoiceOver 标签。
- 键盘可以到达所有鼠标可操作的核心功能。

## 十一、风险与应对

### 11.1 字号提升导致布局溢出

应对：

- 使用 `ViewThatFits`
- 为次级列定义隐藏优先级
- 减少非必要 Badge
- 允许标题换行或进入详情
- 不通过重新缩小字体解决

### 11.2 减少卡片后分组不清晰

应对：

- 使用 16-20pt 组间距
- 使用 Section 标题和单条分隔线
- 保留交互行的 hover 状态
- 只在真正需要边界时恢复弱描边

### 11.3 原生 toolbar 改造影响窗口行为

应对：

- 保留现有 `NSToolbar` 与窗口追踪逻辑
- 分步骤迁移按钮
- 回归双击缩放、标题栏拖动、全屏和窗口恢复

### 11.4 AI 内容折叠后信息发现性下降

应对：

- 摘要必须包含关键结论和风险
- Disclosure 标题显示内容数量和异常状态
- 分析运行时自动展开最新日志
- 失败状态不得隐藏在折叠区域内
